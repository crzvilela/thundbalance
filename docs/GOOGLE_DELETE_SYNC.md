# Sessions deleted in Google Calendar

When an event is deleted directly in Google Calendar, the web cancels its session (`calendar_reconcile.py`): a future pack session (Booked) or trial session (pending / approved / confirmed) that has a `google_event_id` is marked Cancelled (`feed_sequence` + 1, pack numbering x/y unchanged, `cancel_source = 'google'`, event id cleared) and the admin shows "Cancelada desde Google Calendar" with a Restore button (the existing restore flow for packs; trials come back in the state they had and the event is created again). It runs in the background when the admin opens the calendar or the trial sessions list (at most once a minute, with one listing of the date range using `showDeleted=true`, and a direct lookup only for events missing from it) and in a thread every 10 minutes while the server is awake; it never runs inside a request and never keeps Render awake. It only cancels when Google itself confirms the event is gone (404 / 410, or the event comes back with status "cancelled"): an error, timeout, missing permission or empty answer cancels nothing, and sessions the web already cancelled are ignored, so there is no loop. If more than 5 events look deleted in one pass nothing is cancelled and the admin sees "Se han detectado N eventos borrados en Google; revisa antes de cancelar" with a button to confirm (`POST /admin/google-sync/confirm`, which checks Google again). No email or inbox message is sent. Set `GOOGLE_DELETE_SYNC=off` (default `on`) to turn all of it off.
